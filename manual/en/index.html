1. What it is

PhoneGhost is a second address book, separate from the phone's own, that can also host one or more encrypted private address books, each protected by a code you choose.

Private address books are not a hidden feature: the app declares them openly, at first launch and in the store listings. What is hidden is how many exist and whether any exist at all — and this is not a presentational detail but the principle on which everything else is built. There is no list, no counter, no icon that lights up. Not even for you.

2. First launch

This happens once per installation and cannot be skipped.

2.1 The explanation

This is the only point in the app where the mechanism is explained in full. The illustrations say without words what words explain poorly: a private address book's code typed in the search field opens that address book; the administrative code opens a menu, not an address book.

The explanation remains reachable at any time from the administrative menu (§6.1): it is not a screen you see once and lose.

2.2 Preparing the encrypted archive

The app writes here the space that will host private address books — always the same amount, whether you create one, ten, or none. This is why the wait reveals nothing about you: the progress bar moves identically on every installation.

This takes tens of seconds on a 2019 phone. The padlock fills along with the bar, and a reflection passes through it slowly — its purpose is to distinguish "still working" from "stuck", which is the only doubt this screen exists to remove.

2.3 The administrative code

At least 8 characters, with at least one letter and one digit.

It is permanent and unrecoverable: it cannot be changed, reset, or retrieved via a security question. If you forget it, you will no longer be able to create new private address books — those already created remain reachable with their own codes, which are separate from this one.

The confirmation screen exists to say one thing — the one most often misunderstood: the administrative code opens a menu, not an address book.

3. The public directory

An ordinary address book: alphabetically sorted list with section letters, initials avatar (colour derived from the name, not random or manually chosen), search, contact card, edit, delete.

Search ignores accents and capitalisation. Searching nicolo finds Nicolò, and vice versa: names are internally compared in a "folded" form. This applies to first name, last name, and company.

Deletion asks for confirmation via a dialog and is not reversible: inside a private address book there is no system copy from which to recover.

3.1 Creating and editing a contact

First name, last name, company, role, multiple phone numbers and multiple email addresses, each with its own label (mobile, home, work, or a custom one). "Add number" and "Add email" create an additional row.

The photo is tapped at the top: take a picture with the camera or choose from the gallery. It is resized and saved encrypted in a separate file; if permission is denied, the app says so instead of failing silently.

Known limitation. On the contact card, only the first phone number is callable, and nothing indicates this: tapping a second number does nothing. This is a registered defect, not intended behaviour.

4. Importing from your phone's contacts

Import lives in two places, answering two different needs:

  • above the list, until an import has never been attempted — for people opening the app for the first time;
  • in settings, always — for people who want to repeat it.

It can be repeated as many times as you like. Already-present contacts are recognised and skipped, so the directory does not double. Recognition works as follows:

  • if the phone contact has at least one number, it is "already present" when at least one of its numbers is already in the directory;
  • if it has no usable numbers, when the name matches (ignoring accents and capitalisation).

Number takes priority over name intentionally: two different people can share the same name, and the opposite rule would silently delete one of them.

Skips, does not update. An already-present contact is not overwritten with phone data: changes made inside PhoneGhost — labels, custom attributes, aliases — remain yours. The accepted consequence is that if you change someone's number on the phone, a new import adds them as a new contact instead of updating the existing one.

At the end of an import the app always reports what happened, even when there was nothing to do ("No new contacts to import"), because an import that finds nothing and one that never started would otherwise look identical.

Import exists only on the public directory. Private address books never import from the system address book.

5. Custom attributes

Extra fields, defined by you, different for each directory: those from the public directory do not exist inside a private one and vice versa.

5.1 Defining them

Four types: Text (up to 200 characters), Long text, Rating 1–5 (stars), and Date.

Names must be distinct, and comparison ignores accents and capitalisation: "City" and "Cïty" would be the same attribute, not two.

5.2 Choosing one to show in the list

One attribute — only one — can become the subtitle of each row in the directory. This makes the list readable when names alone are not enough to tell people apart.

5.3 Filling and viewing them

Defined attributes appear at the bottom of the editor for every contact in that directory, with the appropriate control for the type. Filled values are visible in the contact card.

Deleting an attribute also deletes the values contacts had for that field, and the confirmation dialog says so.

6. Private address books

6.1 The administrative menu

It opens by typing the administrative code in the directory's search field and pressing enter. There is no other way: no button, no menu entry, no secret gesture.

Three entries: create a new private address book, re-read the first-launch explanation, and change the app icon — the last announced but not yet implemented.

6.2 Creating one

The code you choose is the key used to encrypt the address book. It is not saved anywhere: the key is derived from the stored data, never the code itself.

The rules are the same as for the administrative code (8+ characters, at least one letter and one digit). If the code is not acceptable the app says only "Invalid code": it does not say why, and in particular it never says "this code is already in use" — saying that would reveal that another address book exists.

The code is unrecoverable. There is no reset, no content recovery. The padlock that closes between the two screens is not decoration: it is the only difference between "you still need to choose a code" and "encryption has taken place".

6.3 Opening and using one

Type its code in the search field and press enter: a private address book replaces the public list. This is the only way.

The only sign that you are inside a private address book is the small padlock next to the title — deliberately discreet: someone looking at the screen from a distance sees an address book.

Everything works the same as in the public directory: contacts, search, photos, attributes. Pressing Back closes the address book and its database.

Two declared limitations:

  • from inside a private address book you cannot open another one: the search field there only searches;
  • there is no system import (§4).

6.4 Settings of a private address book

The public directory has import and no ghost-contact policy; a private address book is the exact opposite — no import, but with the ghost-contact management option (§7).

7. Calls and ghost contacts

When you call a contact from a private address book, their name does not exist as far as the system is concerned — it would appear as a bare number in Recents. PhoneGhost therefore creates, a moment before dialling, a ghost contact in the system address book with the alias you chose, so the call log shows a name.

The alias is set in the contact editor, and the field appears only inside a private address book: in the public directory it makes no sense, because those contacts are not private.

The "Ghost contact after call" setting (§6.4) decides what happens to that contact:

SettingEffect
Keep contact (default)The ghost contact stays in the system address book, and the name continues to appear in Recents
Delete contactThe ghost contact is removed immediately after the call
Both choices have a cost. Measured on a Galaxy S10 with the Samsung dialler: deleting the ghost contact causes the name in Recents to disappear immediately, leaving only the number. That dialler does not use the name stored in the call log — it resolves it live from the address book each time. So "Delete" really means no trace in the address book, but no name in Recents either. That is why the default is "Keep".

Behaviour depends on the dialler: a different phone could behave the opposite way. The default is chosen to hold in the worst case.

To hide ghost contacts in the phone's Contacts app, deselect the account it.phoneghost.local under "Contacts to display".

8. Languages and appearance

The app speaks six languages — Italian, English, Spanish, French, German, Portuguese — and follows the phone's language; those who speak none of the six see English.

Light and dark theme, following the system. On iPhone, some screens use native iOS controls.

9. What the app doesn't do

  • It does not write to the call log. Neither platform allows a store-distributed app to do this: ghost contacts exist precisely to work around this limitation lawfully.
  • It cannot use an arbitrary photo as the app icon. Both platforms only allow choosing from icons bundled in the app at build time. The feature is not yet active.
  • It has no inactivity lock, no screenshot block, and no quick-exit. These were planned and the controls were removed: showing them without implementing them would have been a false promise of security.
  • It does not sync and does not back up. No cloud, no account.
  • No favourites, no groups.

The limits of deniability, in full

Private address books hide which storage slots are occupied, and the count is blended with decoy slots. But:

  • someone with access to a unlocked, rooted device can deduce a (decoy-inflated) count through the system keychain;
  • the app's storage grows by 64 KB per photo, and this is readable in System Settings without any tools. Someone who has a copy of the files learns the total number of photos across all address books — but not which address book owns any of them, because file names are random and every file is exactly the same size.

This is not a bug to fix: it is the declared boundary of what the project promises.
